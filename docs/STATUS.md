- اختُبر انتقال تذكرة الكاشير من جديدة إلى التحضير، كما أُرسل طلب ضيف تجريبي وظهر برقم `G-…` في شاشة المطبخ.
- هذا وضع معاينة فقط: لا مبيعات فعلية، ولا API إنتاجية، ولا اتصال أو إرسال إلى زاتكا. بيانات المعاينة لا تُشارك مع زائر آخر.

## ما كان يتيحه مصدر 0.5.0 محليًا (تاريخي)

- **الكاشير والفواتير:** شاشة البيع تنشئ الفاتورة في API المحلية؛ تعرض واجهة تفاصيل الفاتورة المحفوظة وبنودها ودفعاتها من `GET /api/v1/invoices/{id}` لإعادة فتحها وطباعتها.
- **الإيصال والطباعة:** فاتورة عربية/إنجليزية قابلة للمعاينة والطباعة أو الحفظ PDF، بتصميم ورق حراري عرض 80 مم، باركود مستقل Code 128 ورمز QR متجهي واضح. بيانات QR التوضيحية ليست إثبات إرسال أو امتثال.
- **سجل المعاينة:** يُحسب مجموع السجل ومتوسطه من مبالغ الصفوف ذاتها. عند طباعة سجل توضيحي بلا بنود محفوظة، يُعرض إجمالي الملخص فقط ويُخفى تفصيل VAT غير المتوفر بدل تقديمه كفاتورة ضريبية حقيقية.
- **المشتريات والموردون:** إنشاء الموردين وفواتير المورد، استلام كامل للأصناف، تحديث الكمية ومتوسط التكلفة المرجّح، حفظ لقطة السعر/الضريبة/المورد، وحركة مخزون مرتبطة بالمستخدم.
- **الدفعات:** دفعة أولى ودفعات جزئية/كاملة، منع تجاوز الرصيد، قيد منفصل، ومفتاح idempotency لمنع تكرار الدفع أو إعادة المفتاح بمحتوى مختلف.
- **المحاسبة:** دليل حسابات أولي عند الحاجة؛ القيود المنشأة للبيع والشراء والاستلام والدفع والرصيد الافتتاحي متوازنة ومسنودة بالمصدر، مع ميزان مراجعة ودفتر أستاذ وذمم عملاء وموردين.
- **الضريبة:** فئات قياسي/صفري/معفى/خارج النطاق، أسباب عند اشتراطها، نسخ مؤرخة للقواعد ومنع التداخل وحفظ نسخة الضريبة على البند.
- **التقارير:** مبيعات ومشتريات ومدفوعات وذمم وVAT تقديري وتكلفة وربح إجمالي ومخزون، اتجاهات يومية وأفضل منتجات وموردين، فترات بتوقيت `Asia/Riyadh`، وتصدير CSV عربي.
- **الدقة المالية:** الخادم مصدر السعر والخصم والضريبة والمخزون، ويستخدم `Decimal` وتقريب نصف لأعلى؛ تستخدم واجهة المال المحلية وحدات هللة صحيحة (`BigInt`) لتفادي أخطاء الكسور العائمة.
- **التصفير المحلي:** endpoint إداري محلي يعيد التحقق من كلمة مرور حساب المدير وينفّذ الحذف في معاملة ذرية. يمسح المبيعات والفواتير والمشتريات والدفعات والقيود وحركات المخزون والمنتجات والعملاء CRM والموردين؛ ويحفظ المستخدمين وبيانات المنشأة ودليل الحسابات وقواعد الضريبة وإعدادات وسجل زاتكا. سجلات المطاعم والمطبخ والموارد البشرية خارج هذا النطاق. هذا الإجراء غير متاح في الموقع العام.
- **الحماية:** يبقى تسجيل دخول المستخدم المحلي كما هو؛ أزيل طلب كلمة المرور الإضافي عن الكاشير وسجل الفواتير، ويظل مطلوبًا لزاتكا ولتأكيد التصفير. قفل زاتكا في نسخة المعاينة العامة قفل واجهة فقط، وليس حماية بيانات حقيقية.
- **زاتكا والإعدادات:** يمكن الوصول إلى إعداد تكامل زاتكا من إعدادات النظام في التطبيق المحلي. معاينة QR الحالية TLV UTF-8/Base64 من الوسوم 1–5 فقط؛ لا يوجد اتصال خارجي أو إرسال فعلي.
- **شاشات وتشغيل:** واجهات RTL/LTR عربية وإنجليزية؛ تشمل شاشة الكاشير والمطبخ والضيف، وسجل الفواتير، وإعدادات التكامل. الطباعة اختُبرت عبر PDF في Chromium؛ لم تُختبر طابعة مادية.

- `pnpm --dir apps/desktop check` — ناجح.
- `VITE_PUBLIC_PREVIEW=true pnpm --dir apps/desktop build` — ناجح.

- اختبارات API للتصفير تؤكد رفض كلمة المرور الخاطئة بلا حذف، ومسح العملاء CRM، وحفظ المستخدمين ودليل الحسابات وقواعد الضريبة وإعدادات وسجل زاتكا، والإبقاء على سجلات المطاعم والموارد البشرية.
- اختبار بيع آلي على واجهة المعاينة: `32.00` ر.س + `4.80` ر.س VAT = `36.80` ر.س؛ دفع نقدي `40.00` ر.س؛ الباقي `3.20` ر.س. طُبع PDF من صفحة واحدة بمقاس `80 × 270` مم، وتحقق وجود QR SVG وباركود Code 128، بلا أخطاء متصفح.
- اختبار سجل الفواتير التوضيحي: تطابق إجمالي `10,421.50` ر.س ومتوسط `2,084.30` ر.س مع الصفوف الخمسة؛ أخفى الإيصال التجريبي تفصيل VAT غير المتوفر.
- التحقق على الموقع المنشور `v0.5.0`: الكاشير وسجل الفواتير بلا قفل إضافي، شاشة زاتكا خلف قفل المعاينة وتفتح بكلمة المرور المعتمدة، وزر التصفير معطل في العرض العام.

## ما لم تغطه دفعة 0.5.0 (تاريخي)

- الموقع العام **ليس SaaS ذا قاعدة بيانات سحابية**. يلزم قبل معاملات الويب نشر API وقاعدة PostgreSQL بأمان وربط نطاق وHTTPS وإعداد أسرار ونسخ احتياطي واستعادة. حتى ذلك الوقت API وقاعدة البيانات محليتان فقط.
- طباعة الإيصال تُسلَّم إلى مربع الطباعة/الحفظ PDF في المتصفح؛ لا يوجد تكامل مباشر مع طراز طابعة حرارية أو درج نقدي.
- المشتريات تشمل تسجيل فاتورة واستلام كامل؛ لا أوامر شراء أو RFQ أو استلام جزئي أو مرتجعات/إشعار دائن أو حد ائتمان مورّد.
- لا دفعات لاحقة لفواتير العملاء أو تاريخ استحقاق مستقل لها؛ لا مصروفات وأصول وتسويات بنكية وإغلاق فترات/ورديات ومراكز تكلفة ومراجعة محاسب قانوني.
- التقرير الضريبي والهامش **تقديريّان** من البيانات المسجلة؛ ليسا إقرارًا رسميًا أو صافي ربح بعد كل المصروفات. لا تُنشأ قيود تاريخية تخمينية.
- لا عزل كامل متعدد الشركات والفروع/المخازن أو أدوار دقيقة واختبار ضغط/اختراق/استعادة على نشر إنتاجي.
- لا بث حي للمطبخ أو مزامنة للعمل دون اتصال أو وصول الضيف إلى API.
- **رفع الفاتورة إلى الهيئة غير مفعّل:** Phase 2 لزاتكا غير منفّذة؛ لا XML UBL مختوم، ولا CSID أو توقيع/تجزئة/وسوم TLV 6–9، ولا Reporting/Clearance، ولا SDK رسمي أو اختبار بحساب المكلف في Sandbox. لا تُرسل هذه النسخة أي بيانات إلى الهيئة.
- يلزم قبل تطوير الرفع التحقق من أحدث مواصفات بوابة المطورين الرسمية وإعداد حساب المكلف ووحدة EGS واعتمادات Sandbox، ثم اختبار دورة الفوترة فيها. لا تضع اعتمادًا أو مفتاحًا خاصًا في المحادثة أو GitHub.
- لا تمثل هذه الدفعة تنفيذ المواصفة الكاملة أو جاهزية مؤسسية أو عبارة «أفضل برنامج في العالم».
