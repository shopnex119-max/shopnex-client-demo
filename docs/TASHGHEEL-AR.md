# تشغيل SHOPNEX فعليًا (بدون وضع تجريبي)

## ليه كان بيظهر "تجريبي"؟
مفيش ترخيص ولا نسخة تجريبية في الكود. الواجهة كانت بتدخل "وضع العرض" تلقائيًا لو اتفتحت من المتصفح (pnpm dev) بدل تطبيق Tauri. اتعدّل ده في 0.7.1: دلوقتي المتصفح كمان بيتصل بالـ API الحقيقية ويطلب تسجيل دخول.
(وضع العرض بيفضل بس لو بنيت بـ VITE_PUBLIC_PREVIEW=true.)

## الطريقة الأفضل للشغل الفعلي: ملف التثبيت
1. ارفع المشروع على GitHub (Private) وشغّل Actions ← "Windows offline desktop package".
2. نزّل `*-setup.exe` وثبّته. الـ API وقاعدة البيانات بيشتغلوا لوحدهم محليًا.
3. أول تشغيل: أنشئ حساب المالك (كلمة سر 12 حرف+)، وبعدين أنشئ الكاشير من "المستخدمون والصلاحيات".

## للتجربة على الجهاز من المتصفح
1. شغّل الـ API: `scripts/run-api.ps1` (أو `bash scripts/run-api.sh`) واتركها مفتوحة (بورت 8000).
2. شغّل الواجهة: `pnpm install` ثم `pnpm dev` وافتح http://localhost:1420
3. لو ظهرت شاشة "إنشاء حساب المالك" يبقى متصل صح.

## الإشعارات (جديد)
الجرس بقى شغال: أصناف نفدت، أصناف قربت تخلص (5 أو أقل)، مفيش وردية مفتوحة، زاتكا غير مُعدّة. بيتحدث كل دقيقة، والضغط على الإشعار بيفتح الصفحة المعنية.

## قبل ما تفتح لعملاء
- زاتكا المرحلة 2 غير منفّذة: البرنامج لا يرسل أي فاتورة للهيئة.
- مفيش نسخ احتياطي تلقائي، ولا مرتجعات، ولا طباعة حرارية مباشرة. خد نسخة من مجلد `%LOCALAPPDATA%\SHOPNEX ULTIMATE` بشكل دوري.
- لإلزام الكاشير بفتح وردية: أنشئ ملف فارغ `require-open-shift.flag` في نفس المجلد.
