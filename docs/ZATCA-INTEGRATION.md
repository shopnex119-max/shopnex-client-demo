# تكامل ZATCA/FATOORA — الحالة الحالية

## ما يعمل الآن

- اختيار Sandbox أو Production وحفظ اسم المنشأة والرقم الضريبي ووحدة EGS ومسارات الشهادة/المفتاح في قاعدة البيانات المحلية.
- قيمة اعتماد التكامل الاختيارية تمر إلى مخزن اعتماد نظام التشغيل عبر `keyring`. لا يعيد API القيمة بعد الحفظ، ولا تعرضها الواجهة بعد مغادرة حقل الإدخال.
- يوجد فحص محلي لاكتمال حقول ملف المنشأة فقط. استجابة الفحص تصرّح `authority_contacted: false`.
- تعرض شاشة زاتكا محاكاة ربط محلية للاختبار: تفحص وجود الحقول الأساسية في Sandbox وتعرض استجابة افتراضية. تسمح المعاينة العامة بكتابة قيم اختبارية للحقول الأساسية في جلسة المتصفح فقط؛ لا تحفظ المحاكاة بيانات، ولا ترسل طلبًا أو اعتمادًا إلى الخارج، ولا تغيّر حالة الاتصال الحقيقي. تبقى حقول الأسرار والحفظ معطّلة في المعاينة.
- يتضمن وضع المحاكاة تدفقًا تفاعليًا لبدء طلب شهادة تجريبي، وإنشاء رقم طلب ورمز OTP محليين، ثم التحقق من الرمز داخل الواجهة. هذه محاكاة UI فقط؛ لا تُنشئ CSR أو شهادة أو مفاتيح حقيقية.
- `adapter_ready` ثابت حاليًا على `false`. مسار `test-connection` يتوقف برسالة 501 بدل إظهار اتصال زائف.
- تسترجع الفواتير المحلية المحفوظة مع بنودها ودفعاتها للطباعة؛ إيصال البيع يدعم ورقًا حراريًا بعرض 80 مم، وباركود Code 128 مستقلًا عن QR.
- QR المعروض محليًا مرحلة أولى (وسوم 1–5) فقط. الطباعة لا تعني الإبلاغ أو التخليص، وQR المعاينة العامة يحمل بيانات توضيحية غير صالحة للاعتماد.
- تبويب الفواتير يعرض صراحة أن زر الإرسال إلى الهيئة غير مفعّل؛ السجل والوثائق في الموقع العام أمثلة فقط ولا تحفظ بيانات.

## ما يلزم قبل تنفيذ محول إرسال

1. التحقق من أحدث وثائق بوابة المطورين الرسمية وحساب المكلف، وبيان خطوات التهيئة الحالية لنوع الحل/وحدة EGS.
2. تحديد التدفق المنطبق قانونيًا وفنيًا على المنشأة وأنواع مستنداتها، والتمييز بين Clearance وReporting.
3. تنفيذ توليد/تحقق XML والتوقيع وQR باستخدام المواصفة وSDK الرسميين دون اشتقاق حقول أو قواعد من مصادر غير رسمية.
4. اختبار Onboarding والاعتمادات وتقديم/استجابة المستندات في Integration Sandbox، وتوثيق حالات الرفض وإعادة المحاولة وحدودها.
5. إتاحة Production فقط بعد إدخال المستخدم بيانات المنشأة الرسمية واكتمال التحقق المطلوب. لا تنفذ هذه النسخة أي عملية إنتاجية.

لا تتوفر بيانات اعتماد مكلف أو شهادة/مفتاح EGS حقيقيان ضمن هذا المستودع أو المحادثة. يلزم أن يجهّز مالك المنشأة حساب Fatoora وبيئة Sandbox وملفات/اعتمادات الحل من بوابة المطورين، ثم تُطابق تفاصيل API الحالية (المحمية بتسجيل الدخول) وتُختبر قبل تنفيذ محول إرسال. لا يُطلب إدخال الأسرار في GitHub أو المحادثة.
